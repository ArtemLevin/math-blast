## 1. Цель и инварианты

Создать масштабируемый самостоятельный курс по всем 28 темам текущего оглавления, объединяющий теорию, решения, задачи, интерактивные модели, диагностику и индивидуальный прогресс. Педагогическая точность, физическая корректность, доступность и сохранность прогресса обязательны на каждой итерации.

- Сохранить публичные URL, номера глав, существующие ID KAS1 и MB-07, прежний ключ `math-blast-kasatkina-v1-solved` и отдельное состояние авторского блока; точный ключ последнего зафиксировать тестом до изменения.
- Не изменять прогресс математической программы `olympiad_math_plan_v2` и её маршруты побочно.
- Канонические данные — JSON; встроенные данные HTML должны воспроизводимо генерироваться или проверяться на полное равенство. Авторские и адаптированные задачи считать раздельно.
- Различать проекции и модули векторов, указывать систему отсчёта, размерности, допущения, область применимости, условия остановки/столкновения/разворота.
- MathML, SVG с корректными масштабами, отсутствие выдачи готового решения до явного раскрытия; без обязательных внешних CDN/API.
- Ручная отметка ученика не эквивалентна проверенному ответу. Автопроверка только для поддержанных типов, со строго определённой семантикой.
- Права на публичное распространение адаптаций и графических реконструкций проверять отдельно; при отсутствии подтверждения — блокировать новую публикацию спорного материала и использовать оригинальные задачи/разрешённые источники.

## 3. Правила статусов и приоритетов

- P0 — блокирует приёмку/публикацию, потеря прогресса, неверная физика/формула, правовой риск.
- P1 — существенное улучшение устойчивости, масштабируемости и учебного UX.
- P2 — расширение и оптимизация после стабилизации.
- BACKLOG — ожидает очереди; READY — входные условия выполнены; IN_PROGRESS — начата; BLOCKED — конкретный блокер; REVIEW — изменения готовы к проверке; DONE — изменения в main, необходимые проверки прошли, доказательства записаны; DEFERRED — осознанно отложено.
- Для QA дополнительно PASS / FAIL / PARTIAL / NOT_RUN. Для главы DRAFT / PREVIEW / READY_FOR_REVIEW / APPROVED; отсутствие обязательного теста исключает APPROVED.
- Каждая задача имеет неизменяемый ID. Закрытые строки сохраняются; новые задачи получают новые ID, при изменении приоритета указывается причина.
- Реализация на ветке/в PR имеет статус REVIEW до merge и подтверждения требуемых проверок. Документация не подменяет тесты.

## 4. Порядок работ

Ближайшая итерация: **PHY-KIN-01** реализована на ветке, статус REVIEW; требуется merge и подтверждение проверок. Следующая по зависимости — **PHY-KIN-02** (после приёмки KIN-01); PHY-QA-01 допускается параллельно при изоляции. Параллельно допускается безопасное документирование прав и разработка инфраструктуры тестов, если изменения изолированы. После стабилизации — PHY-CORE, затем развитие динамики; аналитика не должна задерживать начало создания новых глав при выполненных обязательных gates.

6. После merge проверить main и Pages; в следующем согласованном PR обновить DONE только при доказанном выполнении критериев, иначе сохранить REVIEW/BLOCKED. Повторно проверить открытые задачи, не объявлять закрытие по одному лишь статусу merge.
