# Инструкции разработки физического блока

Область действия: этот каталог и его подкаталоги. Для изменений общих файлов репозитория, затрагивающих физический блок, применять те же правила наряду с инструкциями верхнего уровня.

## Обязательные документы

- [ROADMAP.md](ROADMAP.md) — каноническая живая дорожная карта, приоритеты, критерии, gates, журнал.
- [methodological-standard-v2.md](methodological-standard-v2.md) — контракт учебного контента.
- [README.md](README.md) — фактический инвентарь глав, данные о проверках и источниках.
- [methodological-review-kinematics.md](methodological-review-kinematics.md) — историческое ревью; сверять актуальность замечаний.

## Рабочий протокол

1. Начать с чтения актуального ROADMAP, main, открытых PR и затрагиваемых файлов. Выбрать постоянный ID задачи и соблюсти зависимости.
2. Создать ветку/PR; указать ID, scope и исходный SHA. В рамках того же PR обновить ROADMAP: статус, результаты, метрики, тесты, блокеры, следующий шаг и журнал. Это обязательно для каждой итерации физического блока, включая незавершённые работы, исправления и инфраструктуру.
3. Сохранять существующие ID задач, маршруты, локальный прогресс и обратную совместимость. Не сбрасывать состояние основной математической программы. Не смешивать оригинальный и адаптированный контент в статистике.
4. JSON считать каноническим. Любые изменения контента синхронизировать с HTML; проверять паритет, ответы, физические модели, MathML, SVG, ссылки, мобильную доступность и релевантные регрессии. Если тест недоступен, фиксировать NOT_RUN и блокировать соответствующий gate.
5. Не объявлять DONE до merge и подтверждения требуемых проверок; на ветке — REVIEW либо BLOCKED. После merge проверить main и Pages, зарегистрировать подтверждение в следующем согласованном обновлении ROADMAP. Не подменять независимое ревью отметками из данных или успехом deployment.
6. Не публиковать новые спорные материалы без подтверждённых прав; сохранять происхождение, печатные ответы и отдельно редакторские исправления. При отсутствии разрешения использовать авторские задачи либо разрешённые источники.
7. Изменять приоритеты с обоснованием; не удалять историю выполненных задач. При изменении фактического наполнения обновлять README и метрики ROADMAP одновременно.

В каждом PR физического блока включать краткий чек-лист: ROADMAP обновлён; ID/прогресс сохранены; JSON/HTML согласованы; релевантные проверки выполнены или явно отмечены; открытые блокеры перечислены. Правила merge действуют согласно настройкам репозитория и разрешению владельца.
